# Стратегия производительности: кеширование и rate limiting

## Анализ производительности

Основные hot paths сервиса:

- `GET /v1/exercises` - часто вызывается клиентом для отображения справочника упражнений
- `GET /v1/workouts/statistics` - считает агрегированную статистику тренировок за период
- `GET /v1/workouts/history` - читает тренировки пользователя и упражнения внутри них
- `POST /v1/auth/login` - публичный эндпоинт, который может получать много запросов и требует защиты от брутфорса

Потенциально медленные операции:

- обращения к PostgreSQL для чтения списков и агрегатов
- JOIN между `workouts`, `workout_exercises` и `exercises`
- повторное вычисление статистики за один и тот же период
- частые авторизации

## Кеширование

Кеш хранится в памяти процесса приложения.

Стратегия: Cache-Aside (Lazy Loading).

Эндпоинт `GET /v1/exercises`:

- кешируется полный JSON-ответ со списком упражнений
- TTL: 60 секунд
- ключ кеша: `postgres:exercises:list`
- инвалидация выполняется при `POST /v1/exercises`

Эндпоинт `GET /v1/workouts/statistics`:

- кешируется JSON-ответ статистики для конкретного пользователя и диапазона дат
- TTL: 30 секунд
- ключ кеша включает `user_id`, `from` и `to`
- инвалидация выполняется при `POST /v1/workouts` и `POST /v1/workouts/{workout_id}/exercises` для текущего пользователя

Для проверки кеша API добавляет заголовок:

- `X-Cache: MISS` - ответ был построен из базы данных и записан в кеш
- `X-Cache: HIT` - ответ был взят из кеша

## Rate limiting

Rate limiting реализован для эндпоинта `POST /v1/auth/login`.

Выбранный алгоритм: Fixed Window Counter.

Параметры:

- ключ лимита: логин пользователя
- лимит: 5 попыток входа в минуту на один логин
- окно: 60 секунд
- при превышении лимита возвращается `429 Too Many Requests`

В ответ добавляются заголовки:

- `X-RateLimit-Limit` - общий лимит запросов в текущем окне
- `X-RateLimit-Remaining` - сколько запросов осталось
- `X-RateLimit-Reset` - через сколько секунд окно будет сброшено

## Метрики для мониторинга производительности

- среднее время ответа и время ответа для 95%/99% запросов по эндпоинтам
- количество запросов в секунду
- количество запросов к PostgreSQL
- количество cache hit и cache miss
- cache hit rate: `hits / (hits + misses)`
- количество ответов `429 Too Many Requests`
- количество ошибок `5xx`

## Проверка

Проверить кеширование списка упражнений:

```bash
curl -i http://localhost:8080/v1/exercises
curl -i http://localhost:8080/v1/exercises
```

Первый ответ должен содержать `X-Cache: MISS`, повторный - `X-Cache: HIT`.

Проверить rate limiting:

```bash
curl -i -X POST http://localhost:8080/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"rate_limit_check","password":"wrong"}'
```

Если выполнить такой запрос больше 5 раз за минуту для одного логина, сервис должен вернуть `429 Too Many Requests` и заголовки `X-RateLimit-*`.
